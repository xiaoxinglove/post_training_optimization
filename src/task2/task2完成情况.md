## 4.1 最小打卡(更新范围与参数高效适配）

1.全参微调、LoRA、QLoRA 的主要收益与代价分别是什么？要对它们做公平比较，至少应固定哪些条件？候选通过验证后，交付形态又该依据哪些因素决定？

收益与代价：全参微调收益是调整空间大，适合需要广泛改变模型行为的任务；代价是梯度、优化器的状态及完整检查点会占用较多资源，训练与存储成本高，且最终效果不是最好。LoRA 只训练指定模块的低秩增量，显著减少可训练参数、优化器状态和适配器文件大小，便于切换与回滚；代价是适应能力受目标模块和秩等配置约束，仍需承担底座前向、反向传播及激活的开销。QLoRA 在低比特量化的底座上训练 LoRA，进一步降低底座权重的显存占用，使有限显存能够容纳更大的模型；代价是引入量化误差、反量化计算及额外兼容性要求，显存更省不等于训练一定更快和效果完全无损。

固定条件：底座、数据及处理方式、监督与评测规则，明确采用相同训练量还是相同资源预算，并给予各方法可比的调参机会。

因素：部署兼容性、资源与性能要求、适配器切换及回滚续训需求选择适配器、合并模型或量化模型。

2.设计适配器的推荐顺序是什么？QLoRA 和 LoRA 变体分别改变什么？为什么它们不是必须依次经过的两个阶段？需要低比特训练时，应记录哪些配置，避免把哪些影响混为一谈？

推荐先明确任务需要哪些模块适应，再确定挂载范围，然后依据可训练参数与显存预算选择秩 \(r\)，设置缩放系数 \(\alpha\)、dropout 和初始化方式，建立标准 LoRA 基线后，再按资源约束考虑低比特底座、按效果瓶颈考虑 LoRA 变体。

QLoRA 主要改变冻结底座的存储与计算路径。LoRA 变体则主要改变适配器更新的参数化、缩放或初始化方式。

因为“底座如何低比特表示”和“适配器如何表达更新”是两个可分别选择的设计维度，不存在必须先训练 QLoRA、再训练 LoRA 变体的依赖关系。

应记录底座模型及版本、量化位宽与类型（如 NF4/FP4）、双重量化开关、计算 dtype、未量化模块与适配器 dtype、量化后端及版本、训练准备方式。



3.选择 LoRA 挂载范围的实质是什么？在低秩旁路中，矩阵 A、矩阵 B、秩 r、缩放系数 α、随机失活分别起什么作用？为什么训练开始时让 B 为零可以保持基座初始行为？

实质是根据模型的位置学习新的调整方式。LoRA 不直接修改原来的权重，而是在选定的位置增加一条可以训练的“小支路”，用它补充和调整原来的计算结果。

**A**先把输入转换成 r 维的中间表示，**B** 再把它转换成与原输出维度相同的调整量；**r** 决定中间表示的维度，越大通常可训练参数越多，能表达的调整也更丰富；**α** 通过 α/r 调节这条支路对最终结果的影响大小；**随机失活**在训练时随机屏蔽一部分支路输入，减少模型对某些输入特征的过度依赖，推理时关闭。

因为模型的最终输出等于“基座输出＋支路调整量”，而 B 为零时，支路调整量就是零，所以在其他条件一致时，模型的初始输出与原来相同。

Q1  
全参微调的收益：效果上限最高，推理无额外开销， 任务无死角适配。  
全参微调的代价：训练成本极高，灾难性遗忘风险，迭代灵活性差，数据门槛高。  
LoRA的收益：训练显存大幅降低，训练效率高、成本低，无灾难性遗忘，灵活可插拔。  
LoRA的代价：效果上限低于全参，场景适配有局限，超参数敏感。  
QLoRA的收益：训练显存极致压缩，精度损失可控，继承 LoRA 全部优势。  
QLoRA的代价：精度损失客观存在，训练速度慢于 LoRA，部署兼容性弱，调参复杂度更高。

公平对比的必控固定条件:

- 基座模型必须一致，必须采用完全相同的预处理权重起点、相同的架构与模型规模
- 训练数据集与数据加载流水线。严格使用完全相同的训练集、验证集、最大序列长度、分词器以及 Batch Size
- 评估基准与测试环境。使用统一的评测集，并借助相同的自动化评测框架输出对比指标。

验证通过后交付形态的决策因素：

- 部署端硬件约束。显存极度有限，优先 QLoRA 量化部署；显存中等可选 LoRA 合并权重；显存充足且追求极致性能选全参微调。算力 / 吞吐量要求高：优先全参或合并后的 LoRA；离线批量场景可接受量化推理的速度损失。
- 业务迭代与多任务需求。迭代频率高、需求多变，优先 LoRA/QLoRA，适配器体积小、训练快、切换成本低，支持快速迭代；长期稳定的核心业务、迭代频率低，可选择全参微调，换取最优效果和最简推理链路。
- 效果与性能的优先级。效果优先、成本不敏感：选择全参微调，获取性能上限；效果达标前提下成本最优，优先 LoRA，性价比最高；资源极度受限时再选择 QLoRA

Q2  
推荐顺序：从轻量到重型、先验证可行性再投入成本，每一步达标即停止，避免过度设计。  
先用标准LORA建立基准；再进行容量扩展，通过增加可训练参数量来提升模型的表达容量；最后进行架构升级或显存极限压榨。

QLoRA改变的是：基座模型的存储精度与内存管理方式。它不改变 LoRA 的低秩数学结构，而是将原本占据绝大部分显存的冻结基座模型权重从 FP16/BF16 压缩为 4-bit，同时引入双重量化和分页优化器，彻底解决了显存爆炸问题。  
LoRA 变体改变的是：适配器本身的参数化方式与更新逻辑。例如，DoRA 改变了低秩矩阵与原权重的组合方式，引入了幅度和方向的权重解耦；LoRA+ 改变了矩阵 A 和矩阵 B学习率配置。它们关注的是如何用更聪明的数学形式提升微调上限

QLoRA 解决的是“底层基座怎么存才能省显存”的问题，而 LoRA 变体解决的是“上层适配器怎么算才能提效果”的问题。他们是可以组合使用的。

1.必须记录的核心配置清单：

- 量化数据类型：具体是 nf4还是 fp4，以及量化块大小。
- 计算精度：前向与反向传播时实际进行计算的数据类型（通常为 torch.bfloat16 或 torch.float16，这与 4-bit 的存储精度不同）。
- 双重量化状态：是否开启 double_quant（对量化常数进行二次量化以节省显存）。
- 优化器与分页配置：是否启用 paged_adamw_32bit 等分页优化器以防止梯度突发尖峰导致的 OOM。
- 目标模块与秩参数：target_modules、Rank ()、Scaling Alpha ()。
2. 避免混淆的三大影响：
- 混淆一：量化噪声与训练欠拟合现象：模型效果不好。避坑：切勿盲目归咎于训练步数不够或学习率不对。4-bit 极端量化带来的基座信息损失是底层的，如果性能不达标，应首先检查是量化精度过高导致的基座能力退化，还是适配器容量不足。
- 混淆二：Wall-clock 时间开销与收敛速度现象：QLoRA 训练跑得极慢。避坑：QLoRA 的慢是由权重的实时反量化计算开销导致的（即硬件物理耗时增加），但这并不等同于模型“需要更多轮次才能收敛”。不要把硬件层面的反量化延迟误解为算法优化效率低。
- 混淆三：计算精度与存储精度现象：认为模型在用 4-bit 进行梯度回传。避坑：必须明确，基座权重在内存中是 4-bit，但在计算时会被反量化为 BF16/FP16，而 LoRA 适配器本身的权重和梯度依然保持高精度更新。切勿混淆两者的精度边界。

Q3  
选择 LoRA 的挂载范围，其本质是在模型表达容量与计算/显存开销之间做权衡。

矩阵A：充当“信息压缩器”。它将高维的输入特征投影到一个极低维的隐空间中。通常采用高斯随机分布初始化  
矩阵B：充当“特征解码器”。它将低维隐空间中的特征重新放大还原到原有的高维输出空间，并叠加回基座模型的输出中  
秩 r：低秩子空间维度。定义低秩更新子空间的维度大小，直接决定适配器的表达能力上限和参数量  
缩放系数 α 与缩放因子 α/r：控制低秩旁路输出的整体幅度，稳定训练过程，降低超参对秩 r 的敏感性  
随机失活：施加在低秩支路上的正则化手段，通常放在 A 矩阵之前或之后，随机丢弃一部分特征，防止适配器过拟合

训练开始时，若 B 为全零矩阵，则低秩更新量为0。此时 LoRA 旁路的输出严格为 0，模型的前向传播结果和原生预训练模型完全一致，没有任何额外随机噪声，完美保留基座的初始行为。
